# DST 营地管理

一个 Docker 容器运行饥荒联机版地面、洞穴和 Web 管理台。页面只保留世界设置、模组管理、存档管理和日志查看。

## 部署

```bash
docker build -t dst .
docker run -d --name dst --restart unless-stopped --stop-timeout 90 \
  -p 8080:8080 -p 10999:10999/udp -p 10998:10998/udp \
  -v "$PWD/runtime/data:/data" \
  -v "$PWD/runtime/server:/opt/dst/server" \
  dst
docker logs dst
```

打开 `http://服务器地址:8080`，使用启动日志中的随机密码登录，右上角可修改密码。首次密码仅在创建时显示；数据卷保留后，升级、重启和恢复游戏存档都不会重置密码。密码以加盐哈希保存，修改后所有会话失效。

首次启动会下载服务端，后续容器启动会检查游戏更新。管理台先启动，可从日志页面查看下载进度。在世界设置中填写 [Klei 服务器 Token](https://accounts.klei.com/account/game/servers?game=DontStarveTogether)，保存后重启服务器即可开服。也可在 `docker run` 加 `-e DST_CLUSTER_TOKEN="你的Token"`，不要把真实 Token 放进代码仓库。

使用已发布镜像时，把构建步骤省略，并将运行命令最后的 `dst` 换成 `chaeoi/dst:latest`。

## 现有存档与默认世界

`runtime/data/Cluster_1` 中有存档时直接使用；目录不存在或为空时，复制程序内的默认模板生成新世界。默认模板为原版生存模式、12 人、地面和洞穴，不包含预先生成的游戏进度或模组。不完整的现有存档会报错，不会被模板覆盖。

可直接把已有存档放到该目录，也可登录网页上传 ZIP 或 tar.gz 后选择恢复。存档至少包含：

```text
Cluster_1/
├── cluster.ini
├── Master/
│   ├── server.ini
│   └── save/…
└── Caves/
    ├── server.ini
    └── save/…
```

包内可保留顶层存档目录，也可直接打包目录内容。上传默认限制 512 MB，解压上限 2 GB，最多 20000 个成员。目录穿越、链接、非常规文件、缺失必要配置的文件包会拒绝。

## 网页管理

- **世界设置**：修改服务器名称、密码、人数，以及地面或洞穴参数。保存保留未展示的配置字段。地形和资源生成参数只影响新生成的世界，不会自动删档。
- **模组管理**：输入创意工坊 ID 添加模组，下载后读取模组的名称、选项说明、可选值和默认值。可增减、启停和修改配置；默认只修改所选分片，明确勾选后才同步到两个分片。添加和下载模组会短暂停服，完成后恢复运行。客户端模组不能添加到服务器。
- **存档管理**：手动备份、下载、上传和恢复。只有点击创建备份才会保存停服、打包并恢复运行。上传只导入存档列表，不覆盖当前世界；点击恢复才替换。恢复不会自动备份当前世界，需要保留时先手动备份。缺失 Token 时沿用当前服务器 Token。
- **日志查看**：查看地面、洞穴、更新、模组下载和面板日志。顶部根据实际子进程显示运行状态，游戏加载是否完成以日志为准。

配置保存后重启服务器生效。读取模组配置支持常见的动态 Lua 表格、循环和中文语言选择；依赖特殊游戏环境或复杂键类型的配置可能无法自动读取，此时保留现有配置并提示原因。不会把“读取失败”当作“没有可配置项”。

没有定时备份、启动备份和配置 `.bak` 文件。游戏自身的自动保存和回档点仍由游戏维护。备份包含完整游戏配置和进度，可能包含服务器 Token，请保管好下载文件。

## 数据与维护

```text
backend/
├── server.py         容器启动入口
├── api/              HTTP 接口
├── services/         分片运行、模组管理和存档业务
└── core/             认证、配置、文件事务和 Lua 读取器
frontend/             原生 HTML、CSS、JavaScript
defaults/             首次开服模板
tests/                回归测试
```

宿主机 `runtime/data` 保存游戏存档、备份、日志和面板认证，`runtime/server` 保存游戏与模组文件；两者都不进入版本控制。恢复只替换游戏存档，不修改面板密码及其他备份。恢复时保留原目录用于事务回滚，安装或启动检查失败时还原；该临时目录不作为历史备份保留。

停止时使用 `docker stop -t 90 dst`，等待两个分片保存退出，不要用强制删除代替正常停服。升级时正常停止并删除旧容器，再用原来的挂载目录启动新镜像。日志超过 10 MB 时轮转，保留三份。

忘记密码时，先停止容器，删除 `runtime/data/.panel/auth.json` 后重新启动，日志会显示新的随机密码。Web 默认为 HTTP；HTTPS 反向代理应保留原始 Host 头，并设置 `DST_COOKIE_SECURE=1`，让浏览器只经 HTTPS 发送登录 Cookie。

可选环境变量：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `DST_CLUSTER_TOKEN` | 空 | 启动时写入服务器 Token，也可从网页填写 |
| `DST_CLUSTER_NAME` | `Cluster_1` | 存档目录名 |
| `DST_WEB_PORT` | `8080` | 容器内面板端口，修改时同步端口映射 |
| `DST_SHUTDOWN_TIMEOUT` | `60` | 等待两个分片保存退出的秒数 |
| `DST_UPLOAD_LIMIT_MB` | `512` | 上传包大小限制 |
| `DST_COOKIE_SECURE` | `0` | HTTPS 访问时设为 `1` |

## 开发验证

Python 3.10 以上、Lua 5.1，无第三方 Python 运行依赖。

```bash
python3 -m unittest discover -s tests -v
```

GitHub Actions 先运行回归测试，再构建发布镜像。日期标签使用提交的作者日期（UTC），当天提交同时更新 `latest`。
